# 使用原始验收模板

模板位于 `assets/templates/`，清单 `manifest.json` 记录原始文件名、版本、SHA-256 和 GitHub 下载地址。用户已要求将三份参考 Word 上传至项目供复用；这些文件保持原字节不变，包含教学／预填样例，不代表最新制度或某次真实采购。

## 选择

| 模板 ID | 原文件 | 用途 |
| --- | --- | --- |
| `self-purchase` | 05-2 深圳科创学院采购验收单（团队自采）(3).docx | 团队自采；含货物／服务明细、验收照片、经办人与辅导老师签字 |
| `goods` | 05-2 深圳科创学院采购验收单（非服务）.docx | 正文为货物类；含五项检查与学院验收意见 |
| `service` | 05-1 深圳科创学院采购验收单（服务).docx | 服务验收与采购项目履约评价，两部分均需保留 |

采购途径与货物／服务是两个维度；自采服务、混合订单的表格组合仍按学院核实结果判断，不能只靠名称一刀切。字段细节见 `decision-guide.json` 的 `acceptance` 节。

## 获取并填写

1. 优先使用与 Skill 同版的随包模板。`scripts/prepare_template.py` 校验哈希并复制到指定的新文件；随包文件缺失时才从清单中的 GitHub 地址下载。校验不符时停止使用该文件，核对仓库版本；不自动接受新文件。
2. 输出到用户私有的 `teams/<team-id>/materials/<case-id>/`。原始模板只读保留；每笔事项填写自己的副本，不能覆盖别人的材料或上一笔已签署文件。
3. 读取 Word 全部表格与合并单元格，先清除样例商品、型号、数量、单价、小计、合计、省略号，以及服务表预填的项目、经办人与部门。样例 `120 × 6 = 720` 与印刷合计 `1950` 不一致，不能带入用户表格。服务验收分项也要核对是否适合本次服务，不虚构现场活动。
4. 从团队／成员档案填稳定字段，从本次事项填业务字段。保留原版式、列序、签名盖章区；按需要增加明细行。未知事实留空并在缺件清单注明，不以示例值填空。签名、结论、评分不由 Agent 捏造。
5. 按 [验收单生成流程](acceptance-generation.md) 整理本次事实，使用 `scripts/fill_acceptance.py` 实际填写；`prepare_template.py` 仍只负责校验与复制，不会填写。检查样例残留、漏页、表格溢出和签字位置。具备渲染工具时渲染检查；无法验证版式时明确标为待检查的草稿。
6. 输出真实 `.docx` 草稿、资采／合思可复制的字段内容、附件清单与缺件说明。记录模板 ID、哈希、生成路径、待签署状态。没有实际交易时不伪造一笔采购来填表。

```bash
python3 scripts/prepare_template.py self-purchase --output /private/path/case-001/验收单待签署.docx
```

仓库中的模板更新用于后续事项；进行中的事项保持已记录版本，确需换表时保留旧文件并重新核对内容。此版本未实现学院系统自动提交；用户拿到表格与填报内容后，按实际系统页面办理。
