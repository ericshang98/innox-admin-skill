## 三种办理方式

| 事项 | API | Computer use | 仍需人提供或完成 |
| --- | --- | --- | --- |
| 提取票据、核对金额、写用途草稿、整理 Word 与附件目录 | 本地即可处理，不依赖学院 API | 一般无需操作界面 | 缺失用途、真实交付与付款事实 |
| 合思预支、报销、劳务等单据 | 官方支持创建、附件上传、提交；学院开通和字段映射待验证 | 已验证首页和模板入口可读、可导航；具体填写、附件上传、保存和提交未测试 | 真实收款信息、适用规则、当前交易授权 |
| 采购申请、合同申请 | 尚未找到学院平台的正式接口文档，不能断言没有 API | 已见入口、采购列表、状态和搜索控件；具体填报控件待验证 | 实际采购需求、报价、合同材料 |
| 建账入库、资产领用／借用、变动、处置 | 尚未确认 | 已见模块入口；表单及权限待逐项验证 | 实物到货、验收、位置和责任人等事实；审批按学院职责完成 |
| 单据状态与历史查询 | 合思有查询接口；资采接口待确认 | 已验证能读取当前账户可见的单据状态 | 超出当前账户权限的事项交相应人员 |
| 登录验证、实际验收、签字盖章、导师／财务审批、付款 | 接口存在也不赋予办理资格 | 可辅助准备及导航，不能代替真人事实与有权人员决策 | 用户或学院对应人员完成 |

默认由 Agent 决定：有已授权、已验证的 API 就调用；没有 API 但运行环境具备 computer use、用户已登录且操作已授权，就通过界面办理。不能仅因缺少 API 就退回手工指南。只有具体控件、权限或真人环节无法代办时，才提供该步骤的填写内容与操作指导。Skill 本身不附送 computer use 工具或企业权限。

## 合思官方接口：文档已核实，学院尚未联调

- [创建单据](https://github.com/ekuaibao/open-platform-docs/blob/main/docs/open-api/flows/creat-and-save.md)：`POST /api/openapi/v2.2/flow/data`。`isCommit=false` 保存草稿；按真实最新单据模板及费用模板组织参数。支持描述、费用明细、附件、关联申请及核销借款等数据，具体字段由租户模板决定。
- [上传附件](https://github.com/ekuaibao/open-platform-docs/blob/main/docs/open-api/attachment/attachment-upload.md)：`POST /api/openapi/v2/attachment/upload`，返回文件标识供单据引用；文档列出单文件最大 30 MB。普通附件上传不等于发票 OCR、验真或查重。
- [提交单据](https://github.com/ekuaibao/open-platform-docs/blob/main/docs/open-api/flows/flow-and-submit.md)：`POST /api/openapi/v2/flow/data/submitFlow`。手动选择节点需要真实流程实例及审批人映射；该接口要求连同自动节点参数完整传入，不能自己改审批链。提交后还要查询状态，可能被费用标准检查驳回。
- [接入凭据说明](https://github.com/ekuaibao/open-platform-docs/blob/main/docs/open-api/getting-started/question-answer.md)：文档说明“合思+ → 开放接口(新)”配置接入凭据；自建应用另有 App ID／Secret。学院是否开通、当前账号是否有配置权、授权范围与当前版本均未验证。管理员凭据不分发给普通成员，不从页面登录令牌拼接公开 API 客户端。

## 已核实的能力与限制

- [提交审批申请](https://developer.work.weixin.qq.com/document/path/91853)：`POST /cgi-bin/oa/applyevent`。自建应用需配置到“审批 - 可调用接口的应用”；代开发／第三方应用需具有“审批”权限。申请人 `creator_userid` 必须在应用可见范围内。2023-12-01 起不再支持新接入使用系统应用 Secret，存量企业例外不能当作新项目方案。
- 同一官方页注明 `use_template_approver=1` 使用后台模板流程，但要求流程中没有“申请人自选”节点；存在这种节点不能机械设置为 1，应先确认学院配置。不可自行指定审批人以绕过学院流程。
- [获取审批模板详情](https://developer.work.weixin.qq.com/document/path/91982)：`POST /cgi-bin/oa/gettemplatedetail`。需要实际 `template_id`；控件 ID、类型、选项与必填项必须读取当前模板，不根据截图位置或显示名称猜 ID。
- 提交接口返回 `errcode=0` 与 `sp_no` 才能记录“已提交”。这不代表审批通过或财务到账。

## 建议架构

本地 Skill 整理事实 → 可版本化的学院规则 → 本地字段草稿与附件清单 → 用户核对 → 学院受控的适配服务 → 官方审批 API → 单号及状态回执。

没有 API 应用授权时，评估已授权的 computer use 路径；运行环境也不能操作时，才提供本地草稿和针对性指南。不要承诺读取用户全部聊天或代用户操作任意企微功能；聊天与审批是不同权限域。

## 重复与未知结果

对本地案件 ID、交易材料摘要、申请人和模板版本记录提交意图。发出请求后若断网或超时，标记 `submission_unknown`，按已获权限查询或让用户查单；无法排除重复时停止重提。不能把本地幂等键称为企业微信接口提供的幂等保证。模板变化后重新读取并复核映射，不复用旧字段 IDs 直接发单。

## 验收条件

用经授权的测试案例验证：普通成员权限不足、模板必填项变化、服务／货物与自采组合、跨阶段费用、缺签名、附件过期、提交超时、重复请求、退回补件、红冲退款。每个状态都需展示下一步与服务端证据。
