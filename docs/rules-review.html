01 / Agent 填写指南

团队信息记住一次，每笔业务单独办理

这份指南规定 Agent 如何准备行政办理材料。当前覆盖采购、验收、预支、核销和报销；团队资料持续复用，每笔事项留下独立记录。

信息层级保存什么什么时候再问
团队长期档案团队／项目名称、预探索或探索阶段及生效日期、经费项目、相关角色、已确认的发票抬头税号。缺少时问一次并保存；用户告知变更、资料冲突或费用跨阶段时，只核对受影响的信息。
成员长期资料办理人的姓名、部门、角色，以及实际办理需要的已核实系统身份和收款资料。同一成员直接沿用；换人办理时读取对应成员资料，不混用个人账户。
本次事项记录买什么、用途、供应商、数量金额、合同总额、付款来源、日期、交付进度、审批单号和本次附件。从本次材料提取，只问影响下一步的缺项；继续办理时沿用这一笔的记录。
  1. 首次使用：建立最小档案

    Agent 从已有信息中提取团队和成员资料，只补问当前办理必需的缺项。确认后保存，后续调用先读档。无需一次填写完整资料表。

  2. 再次办理：先读档，再看新材料

    团队、阶段与成员信息自动沿用；根据新订单或合同记录本次金额、用途、付款与交付，不重复问长期问题。

  3. 阶段发生变化：保存生效日

    例如从预探索转入探索，追加新阶段和生效日期。旧事项保留原来的阶段依据，不因为当前阶段变化而全部改成探索。

  4. 中途回来：接着原事项办

    保存采购、付款、验收和审批进度，读取原单号及材料，告诉用户这次要补什么。不会把每次对话都当成一笔新采购。

记忆实际保存在哪里

本版本提供本地档案读写工具，团队与事项记录保存在用户设备的私有目录，独立于 Skill 安装目录。成功写入后才表示已记住；更换设备需要迁移档案，不自动云同步。用户可要求查看、更正或删除。

02 / Agent 填写指南

读取团队档案，判断本次事项的办理路径

Agent 先读取已确认的团队、成员和阶段信息，再从本次订单、合同或票据提取事实。用户无需重填长期资料，也无需选择流程。

你要办的事进哪个系统已经确认的入口
购买设备、软件或供应商服务；办理采购、合同、入库企业微信 → 资采管理采购：我的采购项目 → 发起采购申请；合同：我的采购合同；入库：建账入库申请。
领取经费预支、个人报销、核销、劳务申请及发放企业微信 → 合思首页 → 新建单据；再按所属阶段与业务匹配模板。
整理发票、写用途、填验收单、补附件先整理材料，之后进入对应系统一笔业务可能先在资采办理，再到合思处理资金。不是二选一。
  1. 读取档案，判断适用阶段

    沿用已确认的团队阶段历史和经费项目，结合本次费用日期及用途判断。仅在信息缺失、变更或跨阶段时补问相关事实。

  2. 再看业务与进度

    采购、劳务和差旅先分开。采购再判断：未买、待审批、已买、已验收、已提单或被退回。已有单据就接着办。

  3. 采购看完整金额

    分别记录合同／订单总额、币种、本次申请付款额、已付款额。单笔分期不能只拿本次付款额决定采购档位。

  4. 财务看谁付款

    个人垫付走报销；学院个人预支款走核销；要先领钱则申请预支；付给供应商另走对公路径。

  5. 最后补验收与专项材料

    货物看实物验收与适用入库；服务看交付与服务验收；境外、劳务、差旅再叠加各自要求。

你的阶段模板怎么处理现在能确定什么
预探索当前账号界面见过“一年制/预探索期学员经费预支”“一年制/预探索期学员费用报销”“一年制/预探索期学员劳务外包申请”。使用前核对当前账号与事项。可按对应业务准备草稿；看到模板不等于费用符合范围。
探索读取探索阶段当前实际模板；不要沿用预探索模板。现有观察仅见过“一年制/探索期学员劳务费发放”这一名称。完整模板清单、预算与可报范围尚未核实，不能替用户猜选。
刚转阶段／阶段未知先核对阶段生效时间与这笔业务的发生日期，再确定经费和模板。先整理现有材料；阶段归属不明时，暂不提交依赖阶段的单据。
第一次使用时，Agent 怎么问

如果材料里没有这些信息，先直接问：“你现在是预探索还是探索？这笔是准备买，还是已经买了？”随后只补问会改变当前路径的金额、用途或付款来源。已有信息不重复问。

03 / Agent 填写指南

还没采购：用金额确定采购路径

以下是培训所述路径，前提是当前阶段和经费允许这笔支出。金额先看完整交易。阈值的累计口径，以及恰好等于 1000／10000 元怎么处理，仍需学院确认。

情况 A

金额明确低于 1000 元

例如单笔 600 元研发配件，没有分期、合并订单等金额口径争议。

现在做什么按培训的小额自采路径准备购买：无需采购申请、无需入库。买完到合思报销或核销。即使只报 100 元，也要验收。
系统入口
采购后，根据付款来源进入合思报销或核销；具体见下一节。
填写内容
先留商品明细、数量、单价和研发用途。收货后在验收表写实际数量、金额、验收日期及结论。
准备材料
订单／明细、发票、实际验收照片或交付证据、适用验收单及真实签署；整理付款记录。
下一步
验收材料齐全后办报销或核销。还没收货时先留材料，不提前写“已验收合格”。

情况 B

金额明确高于 1000 元、低于 1 万元

例如采购一台 5000 元设备，尚未下单。

现在做什么先提采购申请，获批后再购买。批准后系统会弹待办，录入供应商和实际成交金额。货物再验收、入库；服务不入库。
系统入口
企业微信 → 资采管理 → 我的采购项目 → 发起采购申请。
填写内容
写采购名称、研发用途、规格、数量、单价、预算总额和经费项目；已有报价据实附上。具体字段名和必填项按实际页面。培训称这一档一般有项目导师审批节点。
准备材料
需求说明、商品明细／报价；后续补供应商、发票、验收及适用入库材料。
下一步
申请获批 → 采购／选商录入 → 验收 → 适用货物入库 → 合思报销或核销。

情况 C

金额明确高于 1 万元

例如完整设备采购 1.8 万元，尚未采购或签署承诺。

现在做什么在情况 B 的基础上，按培训进入学院采购路径，并准备三家比价。不要直接按团队自采办理。
系统入口
资采管理 → 我的采购项目，按学院采购流程办理；具体分支与负责人须按当前系统核对。
填写内容
整理完整需求、总金额、规格数量、服务范围、交付时间和报价比较。有合同则单独整理付款阶段与验收条件。
准备材料
需求明细、三家报价及比较说明、适用合同材料；后续补验收、发票和入库材料。
下一步
完成学院采购审批及适用合同环节，再按约定采购、付款、验收；供应商付款见下一节对公路径。

情况 D

恰好 1000／10000 元，或金额口径不清

金额压在分界上；合同分期；多件合单；外币折算；总额、本次付款额或累计金额可能落入不同档。

现在做什么先整理全额与分期明细，由学院确认档位。只暂停档位相关的购买、签约或提交决定，继续准备需求和附件。
系统入口
不凭猜测新建某一档审批，也不通过拆单改变路径。
填写内容
并列写合同／订单总额、币种、数量单价、本次付款额、已付款额；说明造成歧义的事实。
准备材料
完整合同／订单、付款约定及报价，不只提供本次付款截图。
下一步
金额口径明确后进入 A、B 或 C。不要自行把等号归到任意一边。
合同多少钱，不等于这次付多少钱

例：合同总额 18000 元，预付 5000 元，已付 0 元。这三个数分别记录，不能据 5000 元直接认定属于中档自采。按完整合同准备学院采购材料，同时核实金额归档口径。是否必须签合同、在哪一节点审批，现有资料没有统一金额标准。已需要办理的合同从“我的采购合同”进入，不能凭采购阈值另造合同门槛。

04 / Agent 填写指南

采购路径确定后，再按谁付款办理资金

采购申请与财务单据可能都要办。下面五种情况由 Agent 根据付款事实匹配，不能用财务申请替代应有的采购审批。培训称预探索和探索都是四类流程：预支、报销／核销、劳务申请、劳务发放。流程类别相同，不等于两阶段可报范围相同。

合思里这类事对应什么不要和它搞混
经费预支还没花，先向学院领一笔个人预支款不是付给供应商的对公预付
费用报销用自己的钱垫付后，把钱报回来选了报销就会再付款；已用预支款的不要改选报销
预支核销花的是之前领到的学院预支款，把原借款核掉核销不再付一笔钱给你
劳务申请／发放付给个人的劳务，先申请，做完再发放不要套普通设备采购表

情况 1

还没付款，想先领学院的钱

团队需要个人预支款，且本笔适用预支。

现在做什么先核对预算、用途及所需采购审批，再准备个人经费预支申请。
系统入口
合思 → 新建单据 → 当前阶段适用的经费预支模板。
填写内容
预支用途、需要预支的本次金额、经费／项目、真实收款账户；有关联采购时保留相应单号与材料。
准备材料
采购需求／预算说明、适用采购审批及真实收款信息。
下一步
培训口径：个人单笔不超过 1 万元；有上笔预支时先核对 70% 核销条件。收到款并支出后转情况 3。

情况 2

已用自己的钱垫付

付款确为个人自有资金，且同笔费用未从学院领取预支或另行报销。

现在做什么完成适用采购、验收及入库后，准备个人垫资报销。
系统入口
合思 → 新建单据 → 当前阶段费用报销模板，按实际页面选择个人垫资对应类型。
填写内容
实际费用、发生日期、用途、经费项目、报销金额、本人真实收款账户；关联应有的采购或出行申请。
准备材料
发票、付款记录、验收及签署；适用采购审批、报价、合同和入库材料。
下一步
按现行流程提交、跟进审批并完成打印交单。培训称一般审批约 2–3 个工作日，付款安排为周二／周四；这不是到账保证。

情况 3

花的是之前领到的学院预支款

已领取个人预支款，本次费用用该款支付。

现在做什么准备个人预支核销，关联原借款／待核销事项。
系统入口
合思 → 当前阶段费用报销／核销对应模板，按实际页面选择核销类型。
填写内容
本次真实支出、核销金额、原预支单号及对应明细；不得把它改选成个人垫资再收一笔钱。
准备材料
本次票据、付款及验收材料、适用入库材料和原预支关联。
下一步
核对系统核销结果及原款剩余金额；有未花余额或退款时按财务要求处理，不擅自抵作下一笔。

情况 4

合同要求学院先付供应商一笔钱

供应商尚未完成交付，合同约定预付款。

现在做什么准备对公预付。已由学院支付预付款的，交付后转对公核销。
系统入口
合思的对公预付／核销对应流程；具体模板名称尚未核实，Agent 需读取当前模板后匹配。
填写内容
合同总额、本次预付金额、比例、付款条件、供应商法定名称及真实对公账户；核销时关联原预付单。
准备材料
合同及适用采购审批、报价或其他付款依据；交付后补票据和真实验收资料。
下一步
对公按合同约定办理，不套个人预支的 1 万元／70% 条件；仍要满足预算、合同与审批要求。

情况 5

已交付，供应商等学院直接付款

用户没有个人垫付，也没有可关联的学院预付款。

现在做什么整理直接对公付款材料，先核实该业务的合思模板和付款前置条件。
系统入口
不能选个人垫资报销，也不能虚构原预付单做核销；直接对公模板尚待核实。
填写内容
真实供应商、合同／订单、交付验收、本次应付金额、累计已付金额及对公收款信息。
准备材料
适用采购审批、合同／订单、发票和验收，货物按适用要求补入库。
下一步
真实模板与付款条件明确后办理对公申请，由学院有权人员完成审批和付款。

05 / Agent 填写指南

货物与服务决定材料，不改变钱的真实来源

先得到采购路径和资金路径，再叠加这一层。服务采购不等于个人劳务；混合订单要保留各部分的真实内容。

你的情况验收怎么填还要做什么
买设备、配件、样机等实物写真实品名、型号、送达数量、单价、小计、合计和验收日期；附实际照片，按实际检查结果填写结论。团队自采优先核对自采验收单的适用性；学院货物采购核对货物类表。适用货物在资采“建账入库申请”办理。
购买软件订阅、设计、加工或其他供应商服务写服务内容、期间、交付物与验收记录；用途写清与研发项目的关系。培训称服务不办理货物入库。自采服务使用哪张验收表仍需核实，不把所有服务机械套进同一张表。
同一订单既有设备也有服务拆明细：设备型号数量金额、服务内容期间金额各自列出；总额核对一致。确认表格组合与货物部分入库；这里拆明细是为了记录交付，不是拆采购金额。
货物还没到／服务还没完成先准备明细与待验收项目，不填已经合格或虚构签字日期。按进度停在采购、预支或合同预付阶段；实际交付后再补验收。

三张验收单，分别填什么

团队自采验收单怎么写不要沿用样例
货物／服务名称、型号参数按实物或订单原文逐项写。模板里的“鼠键套装／宏基鼠键套装”是样例，先清空。
送达数量、单价、金额小计、其他数量乘单价等于小计；币种单独记录。样例行 120 × 6 = 720，合计却印着 1950，不能当作用户交易。
金额合计与各行小计、对应发票合计核对。多张发票可以放进同一张验收单，但明细不能糊成一行。
验收照片附实际收货或交付证据。购买截图能否代替实物照片，尚未确认。
验收内容、验收时间合格或不合格按实际检查填写；日期写真实验收日。还没收到货，不能提前勾合格。
团队经办人、辅导老师签字留给对应的人亲笔签。培训还提到组长；经办人与组长是否同一人，待学院核对。
货物类验收单怎么写还要勾的五项
货物名称、规格型号、数量单价金额与自采表同类，按货物原文填写。交付是否按期、包装完好、能否正常使用。
金额合计、验收照片合计与发票一致；照片是实物。需要安装、培训或施工的，是否已经做完。
学院验收意见、日期留给学院有权人员填写，Agent 不代填结论。发票上的客户名称、金额、数量、品名规格是否与要求一致；保修卡和售后是否明确；是否还要特殊验收。
服务类验收单怎么写履约评价表
项目名称、采购经办人／部门、供应商按真实项目和合同主体。人员配置 20、到岗 30、服务质量 30、协调配合 20。
服务起止时间、验收记录写期间和分项通过／不通过；软件订阅要写清用途，不虚构现场搭建。原表等级：优秀 90–100，良好 75–89，合格 60–74，不合格 ≤59。
验收结论、甲乙双方签名盖章结论和签字盖章由对应人员完成。分项能否套到软件订阅，须另核对，不能机械打满 100 分。
谁来签，按哪张表

自采表有“团队经办人、辅导老师”签字位；培训还提到组长，角色对应关系待学院核对。货物类表有检查项目和学院意见；服务文件另附履约评价。Agent 可以准备表格，但实际结论、评分、签字和盖章由对应人员完成。

06 / Agent 填写指南

把同一笔业务整理成可直接填写的内容

以下是填写内容清单，不假称已经核实每个页面的字段名。Agent 打开实际表单后对应字段填写；没有的字段不编造，已有值不重复问。

资采：采购申请

字段怎么写示例格式（方括号换成真实信息）
项目／采购名称说清项目和所购内容，避免只写“报销”。[项目名]研发测试设备采购
需求／用途写要完成的任务、验证目的及与项目关系，不为了可报而改用途。用于[项目]的[具体测试]，采购[设备]以验证[指标]。
规格与明细名称、型号、数量、单价逐项列出；费用币种单独记录。[型号] × [数量]，单价[金额][币种]。
预算／预计采购额申请时填真实预计金额，成交后按相应环节填真实成交金额。预计总额[金额]；依据[报价／订单明细]。
经费／项目归属匹配真实团队、阶段和经费；不自行造项目或填错年度。选择系统内已确认的[经费项目]。
供应商及附件是否在申请时填写或在后续选商待办填写，以实际页面为准。[供应商法定名称]；附[需求／报价文件]。

资采：合同申请

字段怎么写金额如何避免混淆
合同主体与标的按合同原文记录双方、采购／服务内容及关联采购。学院签约主体不能凭抬头猜填。
合同总额记录全合同金额、币种和合同中的含税约定。例：18000 元，不用预付款 5000 元覆盖总额。
付款安排逐期记录金额／比例、付款条件及已付情况。例：本次预付 5000 元，已付 0 元；余款条件照合同写，不自己编。
履约与验收记录交付时间、地点／方式、交付物及验收条件。尚未发生的交付不要填成已经完成。
合同文件与审批附真实拟签或已签版本，保留其状态及关联采购材料。是否需要、何时提合同审批尚待现行制度核实；提交申请不等于合同已签署。

合思：财务单据

字段怎么写随业务变化的内容
模板／费用类型根据适用阶段、真实业务与付款来源匹配。报销、预支、核销、对公不能按金额相近随便互换。
标题与事由标题写事项，事由写用途和相关业务事实。[项目]的[设备／服务]费用；用于[任务]，关联[采购／借款单号]。
日期与金额日期按字段含义填真实日期；金额按实际支出或本次申请付款填写。发生日、开票日、申请日不同；合同总额与本次付款也不同。
收款信息个人报销填真实个人账户，对公填供应商账户和对应开户支行。预支核销按页面关联原款，不重新指定个人收款来重复领款。
原单关联读取应关联的真实采购、出行、劳务或预支单。核销必须对应原预支／借款事项；不能用文字说明代替系统所需关联。
附件按当前情形上传已有且完整的票据、验收、审批等材料。缺签名、缺票、未验收时，先说明具体缺件，不能用无关材料凑齐。
发票与验收单金额怎么对

可把多张发票放入一份适用验收单，但要保留真实货物／服务明细，核对数量、单价、小计、合计和付款差额。先清空 Word 样例内容；开票抬头、税号使用学院确认资料。购买截图能否代替实物验收照片尚未确认。

08 / Agent 填写指南

把阶段、金额、付款和类型组合起来

以下都是说明判断方式的虚构例子，不是你的真实交易，也不代表相应费用已获学院批准。例子一至三假设适用阶段与经费已确认允许该项支出。

预探索 · 600 元研发配件 · 自己已付款、已收货

单笔人民币 600 元，无分期；自有资金垫付；已实际验收。

判断结果小额自采 + 个人垫资报销 + 实物验收。

  1. 整理订单、发票和付款记录；填自采适用验收表：品名、规格、数量单价、600 元合计、真实验收结果与日期，补照片及签署。
  2. 合思 → 新建单据 → 核对预探索费用报销模板；匹配个人垫资类型，填研发用途、真实发生日、600 元及本人收款信息。
  3. 附材料并按当前流程办理。培训的小额口径下无需采购申请或入库；仍需完成验收和后续交单。

此例还需注意：只补问材料里缺失的具体研发用途、验收或签署，不再让用户选择流程。

探索 · 5000 元设备 · 还没买、希望先领经费

完整单笔人民币采购额 5000 元，个人申请预支也是 5000 元，无上笔未清预支。

判断结果先采购申请 + 个人预支 + 实物验收及适用入库 + 后续核销。

  1. 资采 → 我的采购项目 → 发起采购申请；填设备规格、数量、预算 5000 元、用途、经费项目及报价。获批后再购买。
  2. 核实探索阶段经费预支模板及流程先后要求，准备 5000 元预支申请和真实收款资料；不能复制预探索模板名称。
  3. 收到预支款并采购后，填写真实成交及供应商信息；收货验收，办理适用入库。
  4. 合思按探索阶段核销路径关联原预支，填实际支出并附票据、验收及入库材料，不改选个人垫资。

此例还需注意：探索阶段模板目前尚未完整核实：先完成字段草稿，匹配到真实模板后再办理。

预探索 · 3000 元研发软件 · 已用学院预支款支付

服务期间和研发用途明确，所需事前采购审批已完成；服务已交付且具有验收依据。

判断结果服务采购 + 个人预支核销；不办理货物入库。

  1. 保留采购审批、订单／合同、服务期间、invoice／发票及付款记录，说明软件用于哪个研发任务。
  2. 核实团队自采服务使用的验收表，按真实交付记录填验收；不虚构实物照片。
  3. 合思使用适用的预支核销路径，关联原预支单，填本次实际核销金额。
  4. 若实际以外币支付，叠加境外金额处理；人民币实扣与原币金额分别记录。

此例还需注意：只核对原预支单、服务验收表组合和缺失的交付材料，不按“软件”一词直接判断可报。

合同总额 18000 元 · 供应商要求先付 5000 元

尚未签约或付款；已有合同草案，预付款与合同总额不同。

判断结果先核对完整合同的采购档位，准备学院采购与合同材料；资金侧为对公预付。

  1. 完整记录总额 18000 元、本次预付 5000 元、已付 0 元、币种及约定付款条件；不能只看 5000 元选择自采。
  2. 核实完整金额适用口径；按高于 1 万元的培训路径准备学院采购和三家比价，并办理适用合同环节。
  3. 核实合思对公预付模板，填供应商真实主体与对公收款信息，附合同和应有审批。
  4. 学院预付、供应商交付后再验收，并在对公核销时关联原预付；货物按适用条件入库，服务不做货物入库。

此例还需注意：阶段与经费未提供时先核实；合同审批节点和对公模板均未核实，不能凭该例直接提交。

刚从预探索转探索 · 1000 元旧订单 · 已自行购买

费用跨阶段，金额恰好在边界，且已经购买。

判断结果同时命中阶段归属、金额边界和事前审批三个核对点，先处理例外。

  1. 整理转阶段生效日、下单／付款／开票日、订单总额及是否已有采购审批。
  2. 由财务／采购确认这笔归属阶段、1000 元档位，以及既成采购的补救办理方式。
  3. Agent 先整理真实票据、付款与验收资料，保留原日期；不倒签、不声称当时已经获批。
  4. 三项明确后，再按真实付款来源匹配报销或核销。

此例还需注意：只追问上述缺失事实；不会因为当前显示探索期就替这笔旧订单选探索模板。
